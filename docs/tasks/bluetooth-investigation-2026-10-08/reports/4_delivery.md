# Исправления Bluetooth: выполнено 08.10.2026

На **minisforum-nuc работает 0.3.2**. Реализован
[план](../../../plans/bluetooth-reliability.md), пройдены автоматические
проверки, реальные SET/GET трёх S4 и штатный рестарт.

## Что изменено

| Дефект | Исправление | Проверка |
|---|---|---|
| C1: частичный connect без cleanup | Ошибка/отмена запуска закрывает транспорт до освобождения scan gate. Закрытие идемпотентно; supervisor освобождает драйвер при любом исходе. | Ошибка, timeout и cancel в start_notify; следующий сеанс восстанавливается. |
| C2: поздний ответ подтверждает новый запрос | Waiter ожидает свой request_id; последние 64 завершённых/отменённых ID подавляют поздние дубли. Неизвестный ID может обновить push-состояние, но не подтверждает GET/SET. | Просроченный GET, поздний SET ACK во время readback, unsolicited push; живые ID всех трёх S4. |
| C3: дельта поверх устаревшей базы | CommandBus вызывает атомарный update_state; выбор базы, merge, запись и readback идут под одним локом. | Параллельный опрос изменяет звук; команда скорости сохраняет новое значение звука. |
| C4: orphan waiter после write error | Write входит в try/finally; pending future отменяется, уже полученная ошибка потребляется, ID завершается. | Ошибка записи и отмена SET; следующий GET работает. |
| C5: 4 секунды не хватает на fallback | Разделены ожидание лока и выполнение; запись кадра ограничена целиком. После неоднозначного write error сначала GET; если настройки уже применились, повтор SET не нужен. | Потерянный ACK (3 с) + GET (1,18 с) завершаются успешно одним SET; ожидание poll не расходует бюджет исполнения. |
| C6: disconnect внутри ретраев Bleak завершает будущую сессию | В очередь слушателя передаётся только разрыв уже готовой сессии. Промежуточные callbacks при connect фиксируются с session_ready=false. | Тест падал до исправления; живые ретраи гостиной и детской перестали приводить к ложному завершению сессии. |

Сканер явно ограничивает start/stop, включая cleanup при отмене. В pairing
ограничены вспомогательные D-Bus вызовы; при отмене Pair вызываются
CancelPairing/Disconnect, возвращается известное исходное Pairable,
освобождаются агент и D-Bus. Watchdog не зависает навсегда на reset;
при отмене выключения адаптера пытается вернуть питание.

Логи подключения/отключения, request_id, тип операции, длительность,
попытка и backoff доступны на INFO. Постоянный журнал:
`/opt/easy-breezy/data/logs/easy-breezy.log`, до 60 MiB с архивами.
Compose доставляется вместе с образом; откат восстанавливает оба.
В runbook исправлены недоказанные утверждения о бондах, конкуренции
scan/connect и якобы более глубоком reset через btmgmt.

ограничивают программное ожидание и попытки cleanup; они не гарантируют
восстановления зависшего драйвера ОС или аппаратуры.
