# Xiaomi miIO — локальный протокол (UDP 54321)

Спецификация того, что реализует `server/src/easy_breezy/integrations/xiaomi/`.
Сверено с `xiaomi.humidifier.ha2` (Mijia Purifying Humidifier 3 Pro, Wi-Fi BL602,
прошивка 1.0.9, MCU 0048) 2026-10-27. Эталонные кадры —
`server/tests/golden/miio_frames.json` (данные, руками не менять).

## 1. Кадр

```text
 0      2      4          8          12         16                         32
 +------+------+----------+----------+----------+--------------------------+----------
 | 2131 | len  | 00000000 |   did    |  stamp   |    md5-checksum (16)     | AES-тело
 +------+------+----------+----------+----------+--------------------------+----------
```

- big-endian; `len` — длина всего кадра (заголовок 32 байта + тело);
- `did` — идентификатор устройства (он же `did` в облаке Mi Home);
- `stamp` — секунды с момента старта устройства (его часы, не unix);
- контрольная сумма = `md5(заголовок[0:16] + token + тело)`;
- тело — JSON, AES-128-CBC с PKCS#7: `key = md5(token)`, `iv = md5(key + token)`.

**Hello** — `21310020` + 28 × `ff`, без шифрования. Ответ — заголовок без тела,
`did` и текущий `stamp` устройства, вместо контрольной суммы `ff…`. Токен
hello не требует и не раскрывает.

**Запрос** — `{"id": N, "method": "...", "params": [...]}`; `stamp` запроса =
stamp из hello + прошедшие секунды + 1. Ответ несёт тот же `id`;
ответ-ошибка — `{"id": N, "error": {"code": ..., "message": ...}}`.

## 2. Поведение устройства (полевые факты, ha2)

| Факт | Следствие в коде |
|---|---|
| `get_properties` на 20 свойств (тело ~850 байт) — молчание; 16 свойств (~680 байт) — ответ | опрос пачками по 10 (`MAX_PROPS_PER_REQUEST`) |
| Ответ на неверный токен не приходит вовсе | таймаут ≠ «устройство выключено»: смотрите `error` в `/api/appliances` |
| `stamp` в ответе = stamp устройства, а не запроса | ответ матчится только по `id` |
| Хвост тела после PKCS#7 — без `\0` (у других моделей бывает `\0`) | кодек на всякий случай срезает `\0` |
| Повторная запись того же значения — `code: 0`, без побочных эффектов | можно безопасно проверять запись |
| Чтение сразу после `set_properties` может вернуть старое значение | после команды состояние перечитывается (до 3 раз, пауза 0,7 с), пока не совпадёт с дельтой |
| Полный опрос — 4 запроса; команда между ними даёт смесь состояний | опрос, команда и действие прибора — под одним замком |

Таймаут запроса 3 с, повтор с новым hello — один раз (`MiioTransport.call`).
`OSError` сокета (DNS, «сеть недоступна») превращается в `MiioError`.

## 3. Карта MIoT-свойств ha2

Полная спецификация — <https://home.miot-spec.com/spec/xiaomi.humidifier.ha2>.
Сервис использует (все читаются с `code=0`):

| Поле сервиса | siid:piid | Значения |
|---|---|---|
| `power` | 2:1 | bool, общее питание |
| `fault` | 2:2 | 0 — нет ошибки |
| `humidifier_mode` | 2:3 | 0 constant (по влажности), 1 sleep, 2 favorite, 3 fan |
| `target_humidity` | 2:6 | 40–70 |
| `water_level` | 2:7 | 0–100 % (шаг 5) |
| `humidifier_fan_level` | 2:14 | 0..2 на устройстве ↔ 1..3 в сервисе |
| `humidity` / `temperature` | 3:1 / 3:7 | %, °C (float) |
| `air_quality` / `pm25` / `pm1` | 3:3 / 3:4 / 3:6 | 0..5 / µg/m³ / µg/m³ |
| `purifier_filter_life` | 4:1 | % (фильтр очистки) |
| `humidifier_filter_life` | 15:1 | % (фильтр увлажнения) |
| `screen` / `sound` / `child_lock` | 5:1 / 6:1 / 7:1 | bool |
| `function` | 9:5 | 0 очистка, 1 увлажнение |
| `water_state` | 9:11 | −2 бак снят, −1 мало, 0 норма, 1 полон |
| `purifier_fan_level` | 11:3 | 0..2 ↔ 1..3 |
| `purifier_mode` | 11:4 | 0 auto, 1 sleep, 2 favorite, 3 fan |
| `purifier_favorite_level` | 10:1 | 0..9 — скорость режима favorite очистки |
| `screen_brightness` | 5:2 | 0 auto, 1 bright, 2 medium, 3 dim |
| `display_metric` | 9:21 | 0 PM2.5, 1 PM1, 2 PM10 — что на экране |
| `auto_dry` / `dry_remaining` | 2:11 / 2:12 | сушка фильтра после выключения / минут до конца |
| `overwet_protect` | 2:10 | защита от переувлажнения |
| `status` / `clean_remaining` | 2:13 / 12:3 | 0 idle, 1 сушка, 2 самоочистка, 3 прервана, 4 готово / минут |
| `off_timer` / `off_timer_hours` / `off_timer_remaining` | 13:1 / 13:2 / 13:3 | таймер выключения, 1–8 ч / минут осталось |
| `night_mode` / `night_start` / `night_end` | 9:6 / 9:7 / 9:8 | ночной режим, минуты от полуночи* |

\* В спецификации 9:6–9:8 без названий; смысл выведен по значениям прибора
(вкл, 1380 и 600 — 23:00–10:00). 5:4 — ещё один выключатель экрана с неясным
смыслом, не используется. Длительность таймера и часы ночного режима пишутся
раньше включения.

Действия — метод `action` с `{did, siid, aiid, in: []}`: самоочистка 12:1 /
12:2 (старт/стоп), сушка фильтра 9:7 / 9:8, сброс ресурса фильтров 4:1
(очистка) и 15:1 (увлажнение).

Запись — `set_properties` с `[{did, siid, piid, value}]`; функция (9:5) пишется
первой, так как режимы зависят от неё. Не используются: самоочистка (12),
самодиагностика (14), отладочные поля 9:3/9:4 (сброс счётчиков фильтров —
для этого есть действия 4:1 и 15:1).

## 4. Токен

16 байт (32 hex), выдаётся облаком при привязке устройства в Mi Home; меняется
при повторной привязке. Получение — Xiaomi Cloud Tokens Extractor
(`docs/xiaomi.md`). Токен — секрет: только `.env`, в тестах — фиктивный.
