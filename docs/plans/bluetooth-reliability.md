# Надёжность Bluetooth на minisforum-nuc

Основание: [исследование 08.10.2026](../tasks/bluetooth-investigation-2026-10-08/reports/0_investigation.md).
Цель — устранить воспроизведённые C1–C5 и сохранить данные для разбора
следующего сбоя. Причина конкретного исчезновения детской пока не доказана.

## План

1. **Жизненный цикл.** Закрывать частично открытый транспорт при ошибке и
   отмене запуска, до освобождения общего scan gate. Ограничить временем
   операции сканирования, D-Bus pairing и watchdog; cleanup тоже ограничен.
   Дополнение по живой проверке 0.3.1: промежуточные disconnect callbacks
   внутренних ретраев Bleak не завершают будущую успешную сессию (C6).
2. **Достоверность состояния.** Сопоставлять ответы с request_id. Поздние
   ответы недавних завершённых/отменённых запросов не обновляют кэш и не
   завершают новый запрос. Неизвестные ID сохраняют поддержку push-состояния.
   SET ACK остаётся необязательным: итог всегда проверяет отдельный GET.
3. **Команды.** Выбирать базу и применять дельту под одним локом драйвера.
   Освобождать waiter при любом исходе записи. После неопределённой записи
   сначала читать состояние. Разделить ожидание лока и выполнение; бюджет
   выполнения покрывает GET базы, SET и контрольный GET. Сброс фильтров
   по-прежнему не повторяется автоматически.
4. **Наблюдаемость и остановка.** INFO: этап/длительность подключения,
   причина ошибки, попытка, backoff, ID/длительность запросов, завершение
   сессии. Файл с ротацией в существующем data volume (до 60 MiB).
   Docker получает 60 секунд на штатную остановку.
5. **Выкат 0.3.2 (после проверки 0.3.1).** Доставка compose вместе с образом, откат обоих при
   провале health. Резервная копия БД и конфигурации; проверка версии,
   свежих данных всех трёх бризеров и сохранности настроек. Отдельный
   штатный рестарт проверяет сохранность журналов и закрытие соединений.

## Проверки

- Регрессии C1–C5 на фейковом транспорте; ошибка/отмена start_notify;
  просроченный GET и SET во время нового GET; unsolicited push;
  параллельный опрос и дельта; write failure/cancel; медленный readback.
- Зависшие scan, D-Bus и watchdog завершаются с ограниченным cleanup.
- Существующие протокольные golden-тесты, filter reset и backoff;
  `make lint`, `make test`, сборка UI и образа, проверка Ansible/compose.
- NUC: все три устройства ONLINE, несколько последовательных опросов,
  логи переживают пересоздание контейнера; штатный stop без SIGKILL.

## Границы

Не меняем ядро, BlueZ, прошивку, USB autosuspend, бонды и политику
общего reset адаптера. Не добавляем новый менеджер Bluetooth. Ресурс
фильтров повторно не сбрасываем. Qingping без физического датчика не
квалифицируем. Сбои радио/USB на реальном оборудовании не инъектируем.

## Результат

Выполнено 08.10.2026, на NUC работает **0.3.2**.

- C1–C5 исправлены; C6 обнаружен при живой проверке 0.3.1, воспроизведён
  отдельным тестом и исправлен в финальном образе.
- `make lint`, 324 теста сервера + 39 UI, покрытие 88,22%, сборки и
  проверки конфигурации прошли.
- Три реальные команды текущей скорости завершились за 0,27–0,57 с,
  все настройки сохранены. HCI подтверждает совпадение ID 3 SET и 3 GET.
- Проверочный рестарт: shutdown 2,36 с, exit 0; три бризера ONLINE за
  9,91 с. Далее по 12 успешных GET без предупреждений/ошибок BLE.
- Предыдущая часть журнала пережила пересоздание контейнера побайтно.
