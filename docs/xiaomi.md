# Приборы Xiaomi (Wi-Fi, miIO)

Поддержан **Mijia Purifying Humidifier 3 Pro** (`xiaomi.humidifier.ha2`) —
увлажнитель-очиститель. Управление локальное (UDP 54321 в LAN), облако нужно
один раз — получить токен. Протокол — [docs/protocol/xiaomi-miio.md](protocol/xiaomi-miio.md).

## Что умеет сервис

- Карточка на главной: питание, функция (увлажнение/очистка), режимы, целевая
  влажность (40–70 %, шаг 5), скорость, экран, звук, блокировка кнопок; вода,
  ошибки, ресурс обоих фильтров.
- Встроенные датчики (влажность, температура, PM2.5) — датчик
  `xiaomi_miio:<did>` появляется сам при первом опросе: графики, триггеры.
  **Комнату прибору задаёт комната этого датчика** (Настройки → датчики).
- Сценарии: цель «Прибор · <имя>» (питание, функция, режимы, целевая
  влажность) — дальше расписания и триггеры запускают такие сценарии.

Ограничения: у приборов нет журнала команд, manual-hold и Яндекса (бризерные
механизмы). Команда из сценария уходит фоном; итог — в логе
(`appliance_command`, `scenario_appliance_failed`) и на карточке.

## Подключение

1. **Токен и did.** Xiaomi Cloud Tokens Extractor
   (<https://github.com/PiotrMachowski/Xiaomi-cloud-tokens-extractor>), вход по
   QR-коду, сервер `cn` для китайских устройств. Нужны `ID` (did), `IP`, `TOKEN`.
2. **Постоянный IP.** Закрепите IP прибора в DHCP роутера — адрес задаётся явно.
3. **`.env` на сервере** (JSON одной строкой, без кавычек вокруг — docker
   `env_file` передаёт их как есть):

   ```bash
   EB_XIAOMI_DEVICES=[{"did":2232120756,"host":"192.168.1.51","token":"<32 hex>","name":"Хлюпик"}]
   ```

4. Перезапуск сервиса. В логе — `appliances_started`, затем
   `appliance_online` и `sensor_registered`.

## Диагностика

| Симптом | Причина |
|---|---|
| `нет ответа за 3.0 с`, hello проходит | неверный токен (прибор перепривязан в Mi Home → новый токен) |
| hello не проходит | IP сменился / прибор не в сети / сервер в другом сегменте LAN |
| `прибор отклонил: <поле>` | свойство не пишется в текущем состоянии (например, режим при выключенной функции) |

Причина последнего сбоя опроса — поле `error` в `GET /api/appliances`.
