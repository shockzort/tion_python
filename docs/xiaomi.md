# Приборы Xiaomi (Wi-Fi, miIO)

Поддержан **Mijia Purifying Humidifier 3 Pro** (`xiaomi.humidifier.ha2`) —
увлажнитель-очиститель. Управление локальное (UDP 54321 в LAN), облако нужно
один раз — получить токен. Протокол — [docs/protocol/xiaomi-miio.md](protocol/xiaomi-miio.md).

## Что умеет сервис

- Карточка на главной — одна на прибор. Свёрнута: показания (как у датчика)
  и режим одной строкой. Развёрнута — ручное управление: питание, функция
  (увлажнение/очистка), режимы, целевая влажность (40–70 %, шаг 5), скорость,
  свой уровень очистки (0–9), таймер выключения (1–8 ч); вода, ошибки,
  ресурс обоих фильтров.
- **Настройки прибора** (Устройства → датчик прибора → «Настроить» или
  «Настройки прибора…» в карточке): экран и его яркость, показатель частиц на
  экране, звук, блокировка кнопок, ночной режим (с … по …), сушка фильтра
  после выключения, защита от переувлажнения; самоочистка, сушка, сброс
  ресурса фильтров (с подтверждением).
- Встроенные датчики (влажность, температура, PM2.5) — датчик
  `xiaomi_miio:<did>` появляется сам при первом опросе: графики, триггеры.
  На главной отдельной карточкой не показывается — его показания в карточке
  прибора. **Комнату прибору задаёт комната этого датчика** (Устройства →
  датчики).

Режимы: «Избранный» режим увлажнения включается только из Mi Home (своей
скорости в протоколе у него нет) — в карточке он виден, если включён, но не
предлагается. «Свой уровень» очистки — это «Favorite» прибора: постоянный
обдув с уровнем 0–9.
- Сценарии: цель «Прибор · <имя>» (питание, функция, режимы, целевая
  влажность) — дальше расписания и триггеры запускают такие сценарии.

## Поддержание влажности — два способа

| | Пресет в сценарии | Регулятор (триггер) |
|---|---|---|
| Где | Сценарии → действие прибора → «Поддерживать влажность» | Триггеры → «Поддержание влажности» |
| Кто держит | сам прибор, режим «По влажности» | сервер, по выбранному датчику |
| Датчик | встроенный (стоит у выхода пара) | любой с влажностью (Qingping, MQTT, сам прибор) |
| Цель | 40–70 % | 20–90 % |
| Без сервера | работает | нет |

Регулятор двухпозиционный: ниже `цель − зона` (по умолчанию 3 %) —
включить увлажнение в режиме «по скорости» на заданной скорости (1–3), выше
`цель + зона` — выключить прибор; кулдаун 5 мин (прибор инертен). Окно
времени и включение из сценариев — как у поддержания CO₂; на одном приборе
активен один регулятор. Ручное выключение регулятор не уважает (manual-hold
у приборов нет): выключите триггер, если прибор нужен для очистки.

Ограничения: у приборов нет журнала команд, manual-hold и Яндекса (бризерные
механизмы). Команда из сценария уходит фоном; итог — в логе
(`appliance_command`, `scenario_appliance_failed`) и на карточке.

## Подключение

1. **Токен и did.** Xiaomi Cloud Tokens Extractor
   (<https://github.com/PiotrMachowski/Xiaomi-cloud-tokens-extractor>), вход по
   QR-коду, сервер `cn` для китайских устройств. Нужны `ID` (did), `IP`, `TOKEN`.
2. **Постоянный IP.** Закрепите IP прибора в DHCP роутера — адрес задаётся явно.
3. **`.env` на сервере** (JSON одной строкой, без кавычек вокруг — docker
   `env_file` передаёт их как есть):

   ```bash
   EB_XIAOMI_DEVICES=[{"did":2232120756,"host":"192.168.1.51","token":"<32 hex>","name":"Хлюпик"}]
   ```

4. Перезапуск сервиса. В логе — `appliances_started`, затем
   `appliance_online` и `sensor_registered`.

## Диагностика

| Симптом | Причина |
|---|---|
| `нет ответа за 3.0 с`, hello проходит | неверный токен (прибор перепривязан в Mi Home → новый токен) |
| hello не проходит | IP сменился / прибор не в сети / сервер в другом сегменте LAN |
| `прибор отклонил: <поле>` | свойство не пишется в текущем состоянии (например, режим при выключенной функции) |
| `appliance_unreachable` в логе сразу после старта | то же, что первые две строки: прибор не ответил ни разу |

Причина последнего сбоя опроса — поле `error` в `GET /api/appliances`.
